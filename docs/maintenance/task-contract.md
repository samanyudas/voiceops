# Task contract

Use this structure for a substantial task or implementation issue.

## Problem

Describe the user's observed problem and the expected behavior.
Include reproduction evidence when a bug exists.

## Scope

Name the affected surfaces, acceptance criteria, and non-goals.
Identify the accepted spec and relevant domain decisions.

## Verification

Name the highest useful behavior boundary.
List exact commands and the user path that can establish success.
Record the baseline before implementation.
Keep unverified behavior explicit.

## Review and handoff

Classify risk and name the required reviewer.
Record the branch, intentional changes, verification output, remaining work, and blockers.
Identify release-tracked issues without closing them at merge.
