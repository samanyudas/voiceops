# Domain documents

VoiceOps uses a single-context layout.
The project root contains `CONTEXT.md` and `docs/adr/`.

## Read domain guidance

Read `CONTEXT.md` before domain exploration or design.
Read ADRs that concern the area of work.
If a domain document is absent, continue with the available evidence.

## Use the glossary

Use the glossary's terms in specs, issues, designs, and tests.
Record a missing domain term for the domain-modeling workflow.
Keep implementation details outside the glossary.

## Respect decisions

Identify an ADR conflict before a proposal changes an accepted decision.
Explain the conflict and the reason for the proposed change.
